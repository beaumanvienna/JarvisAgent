# AIAssistant::Application Class

Abstract base class defining the interface for an AI assistant application's lifecycle and event processing.

## Methods

- **virtual ~Application() = default;**  
  Virtual destructor for proper cleanup.

- **virtual void OnStart() = 0;**  
  Called once at application start for initialization.

- **virtual void OnUpdate() = 0;**  
  Called repeatedly to update application state.

- **virtual void OnEvent(std::shared_ptr<Event>&) = 0;**  
  Handles incoming events.

- **virtual void OnShutdown() = 0;**  
  Called once before application exit for cleanup.

- **virtual bool IsFinished() const = 0;**  
  Indicates if the application has finished running.

## Usage

Inherit and implement all pure virtual methods to define custom AI assistant application behavior. The framework uses these methods to manage app lifecycle and event handling.

## struct ProbFileInfo

Stores metadata parsed from a problem file's name.

| Member    | Type   | Description                      |
|-----------|--------|--------------------------------|
| `id`      | `uint64_t` | Numeric identifier of the problem file. |
| `timestamp` | `int64_t`  | Timestamp extracted from the filename.   |
| `isOutput` | `bool`     | Flag indicating if the file is an output (`true`) or input (`false`). |

---

## Functions

### `std::optional<ProbFileInfo> ParseProbFilename(std::string const& filename)`

Parses the given filename to extract problem file metadata if it matches the expected pattern.

#### Parameters  
- `filename` - The filename string to parse.

#### Returns  
- `std::optional<ProbFileInfo>` containing parsed information if the filename is valid.  
- `std::nullopt` if the filename does not follow the expected format.

#### Filename format  
- Must start with `"PROB_"`.  
- Must end with either `".txt"` (input file) or `".output.txt"` (output file).  
- Must adhere to the pattern:  
  `PROB_<id>_<timestamp>.txt` for input files and  
  `PROB_<id>_<timestamp>.output.txt` for output files.

#### Parsing details  
- Extracts `id` between the first and second underscore.  
- Extracts `timestamp` between the second underscore and file extension.  
- Sets `isOutput` based on file extension.

---

### `bool IsProbFile(std::string const& filename)`

Returns whether the given filename conforms to the problem file pattern.

#### Parameters  
- `filename` - The filename string to check.

#### Returns  
- `true` if `filename` matches the problem file pattern.  
- `false` otherwise.

---

## Usage Summary

This utility enables robust identification and metadata extraction from filenames following a strict convention designed for problem input and output files, assisting both humans and AI in handling these files efficiently.

# TrackedFile Class Documentation

## Overview
`TrackedFile` is a C++ class designed for efficient tracking of file modifications. It facilitates monitoring content changes and managing file metadata, enabling both humans and AI systems to quickly detect updates and retrieve file content when needed.

## Namespace
`AIAssistant`

## Dependencies
- C++17 standard filesystem library (`<filesystem>`)
- `<string>`, `<atomic>`, `<mutex>`, `<fstream>`, `<sstream>`, `<optional>`
- Optional: OpenSSL (`<openssl/sha.h>`) for SHA256 hashing (fallback to `std::hash` if OpenSSL is unavailable)
- Project-specific: `fileCategory.h`, logging (`log/log.h`), and `engine.h`

---

## Class: `TrackedFile`

### Purpose
Represents a file tracked for changes by calculating and storing a hash of its content. It can mark itself as modified, check if the file content changed on disk, and provide file content on demand.

### Constructor
```cpp
TrackedFile(fs::path const& path, FileCategory fileCategory);
```
- **Parameters:**
  - `path`: Filesystem path to the tracked file.
  - `fileCategory`: Category classification of the file (enum type `FileCategory`).
- **Behavior:** Initializes tracking for the file, computes the initial content hash, and marks it as modified.

---

### Member Functions

#### `bool IsModified() const`
- **Returns:** `true` if the file is currently marked as modified; otherwise `false`.
- **Thread-safe:** Uses atomic variable.

#### `fs::path const& GetPath() const`
- **Returns:** The filesystem path of the tracked file.

#### `void MarkModified(bool modified = true)`
- **Purpose:** Manually mark or unmark the file as modified.
- **Parameters:** 
  - `modified`: `true` to mark as modified (default), `false` otherwise.

#### `std::string GetContent()`
- **Purpose:** Reads and returns the full content of the tracked file as a string.
- **Side Effects:** Does **not** modify the modified flag.
- **Thread-safe:** Uses mutex to synchronize file access.
- **Failure:** Logs a warning and returns empty string if the file cannot be opened.

#### `FileCategory GetCategory() const`
- **Returns:** The category of the tracked file.

#### `bool CheckIfContentChanged()`
- **Purpose:** Checks if the file content changed by recomputing the hash and comparing against the stored hash.
- **Returns:** `true` if the content differs from the last stored hash; otherwise `false`.
- **Side Effects:** Updates the stored hash to the new value if changed.
- **Thread-safe:** Uses mutex to synchronize file reading and hash comparison.

---

### Private Member Functions

#### `std::string ComputeFileHash() const`
- **Purpose:** Computes a SHA256 hash of the file content if OpenSSL is available; otherwise falls back to `std::hash`.
- **Returns:** Hexadecimal string of SHA256 hash or string-converted fallback hash.
- **Failure:** Returns empty string on failure to open file.

---

### Member Variables

| Variable       | Type               | Description                                   |
| -------------- | ------------------ | ---------------------------------------------|
| `m_Path`       | `fs::path`         | Filesystem path of the tracked file.         |
| `m_FileCategory`| `FileCategory`     | Category enum of the file.                     |
| `m_Modified`   | `std::atomic<bool>`| Flag indicating if the file is marked modified. Initialized to `true`. |
| `m_LastHash`   | `std::string`      | Stores last computed hash of the file content.|
| `m_Mutex`      | `std::mutex`       | Protects concurrent reading and hash checking.|

---

## Usage Summary
- Instantiate with file path and category.
- Use `IsModified()` to check if the file is flagged as modified.
- Call `CheckIfContentChanged()` to detect real file changes by content.
- Use `GetContent()` to retrieve file data.

- **SetRegistry()**: Assigns a pointer to the `WorkflowRegistry` for workflow definitions lookup.

### Workflow Execution

- **EnqueueWorkflowRun(workflowId)**: Adds a workflow identified by `workflowId` to the queue for execution.
- **TryGetLastRun(workflowId, outRun)**: Retrieves the last executed workflow run state for a given `workflowId`.

## Internal Workflow Handling

- **StartPendingRuns**: Transforms queued workflow IDs into active workflow runs, initializing task states as pending.
- **TickActiveRun**: Steps through each active workflow run:
  - Harvests completed tasks by fetching future results.
  - Dispatches newly ready tasks asynchronously.
  - Performs freshness checks to skip redundant tasks.
  - Detects deadlocks and marks runs failed if no progress can be made.

- **IsRunTerminal**: Checks whether all tasks in a run have reached terminal states (`Succeeded`, `Skipped`, or `Failed`).

---

## Task Execution

- **ExecuteTaskOnWorker**: Runs a single task on a worker thread:
  - Resolves task inputs using the `DataflowResolver`.
  - Calls the registered `TaskExecutorRegistry` to perform task execution.
  - Updates task execution state and output values.
  - Distinguishes between successful, failed, skipped, or waiting states.

- **DrainAiRequestCompletions**: Processes queued AI request completions from the `AiRequestPool`.
- **TryApplyAiCompletion**: Applies an AI request completion to the matching workflow task state or defers it for retry.

## Thread Safety

- Protected by a mutex to safely manage active runs, pending runs queue, and workflow registry pointer.
- Designed to be called from the main thread, ensuring UI/event loop responsiveness.

- simdjson for efficient JSON parsing.
- C++17 `<filesystem>` for path handling.

- File watch trigger paths are normalized relative to workflow base or file directory if not absolute.
- File watch events include Created, Modified, Deleted; invalid entries are logged and ignored.
- Debounce value is clamped to valid `uint32_t` range.
- Errors in JSON parsing cause affected triggers to be skipped.

# KeyboardInput Class Documentation

Namespace: `AIAssistant`

## Overview
`KeyboardInput` provides asynchronous keyboard input handling for both Windows and Unix-like systems. It listens for key presses without blocking the main thread and posts relevant events to the application core.

---

## Public Methods

### `void Start()`
- Begins listening for keyboard input.
- Has no effect if the listener is already running.
- Launches the listener in a separate thread via the application's thread pool.

### `void Stop()`
- Stops the keyboard input listener if it is running.
- Waits for the listener thread to exit gracefully before returning.
- Logs the shutdown of keyboard input.

---

## Private Methods

### `void Listen()`
- Core input listening loop running on a background thread.
- For Unix-like systems:
  - Configures the terminal in raw mode (non-canonical, no echo).
  - Uses `select()` for non-blocking keyboard input polling.
- For Windows:
  - Uses `_kbhit()` and `_getch()` to detect and retrieve key presses.
  - Includes a 100 ms sleep between polls to reduce CPU usage.
- Posts these events on key press:
  - Quit key (`'q'` or `'Q'`): posts an `EngineEventShutdown` event and exits.
  - Other keys: posts a `KeyPressedEvent` with the pressed character.
- Restores terminal settings on Unix-like systems on exit.

---

## Member Variables

- `std::atomic<bool> m_Running`  
  Indicates if the listener thread is currently active.

- `std::future<void> m_ListenerTask`  
  Holds the future for the asynchronous listening task, allowing controlled shutdown.

---

## Usage Summary
Instantiate `KeyboardInput`, call `Start()` to begin listening for key presses in the background, and `Stop()` to terminate listening. Key input results in events pushed to the application core, enabling decoupled processing of user keyboard interaction. The class supports graceful shutdown triggered by pressing 'q' or 'Q'.

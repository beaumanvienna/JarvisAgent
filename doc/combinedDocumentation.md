# AIAssistant::Application

Abstract base class defining an application's lifecycle and event handling interface within the AIAssistant namespace.

## Overview

`Application` outlines the essential methods for managing an application’s lifecycle phases—start, update, event processing, and shutdown—and provides a query to determine if the application has finished running.

## Member Functions

- `virtual ~Application() = default;`  
  Ensures proper destruction of derived classes.

- `virtual void OnStart() = 0;`  
  Initialization logic executed once when the application starts.

- `virtual void OnUpdate() = 0;`  
  Called periodically to update the application state.

- `virtual void OnEvent(std::shared_ptr<Event>&) = 0;`  
  Handles incoming events via shared pointers.

- `virtual void OnShutdown() = 0;`  
  Cleanup logic executed once before application termination.

- `virtual bool IsFinished() const = 0;`  
  Indicates whether the application has completed execution.

## Usage

Subclass `Application` and implement all pure virtual functions to define specific application behavior.

```cpp
class MyApp : public AIAssistant::Application {
public:
    void OnStart() override { /* init code */ }
    void OnUpdate() override { /* update code */ }
    void OnEvent(std::shared_ptr<Event>& event) override { /* event code */ }
    void OnShutdown() override { /* cleanup code */ }
    bool IsFinished() const override { return finished; }
private:
    bool finished = false;
};
```

## Remarks

- Enforces a structured, event-driven application lifecycle.
- Uses `std::shared_ptr<Event>` for safe event memory management.

# FileWatcher Class Documentation

Namespace: `AIAssistant`

---

## Overview

`FileWatcher` monitors a directory recursively for file additions, modifications, and removals at regular intervals. It issues specific events upon detecting these file system changes.

---

## Purpose

Provides asynchronous polling-based file system monitoring to enable reactive application or AI behaviors based on file changes.

---

## Public Interface

### Constructor

```cpp
explicit FileWatcher(const fs::path& pathToWatch, std::chrono::milliseconds interval = 100ms);
```

- `pathToWatch`: Directory path to monitor
- `interval`: Polling interval between scans (default: 100 ms)

### Destructor

```cpp
~FileWatcher();
```

- Stops the watcher if running before destruction

### Methods

- `void Start()`: Starts asynchronous monitoring; no effect if already running
- `void Stop()`: Stops monitoring and waits for background task completion; no effect if not running

---

## Functional Behavior

- On start, recursively scans all valid files and emits `FileAddedEvent` for each
- Periodically rescans directory:
  - Emits `FileAddedEvent` for new files
  - Emits `FileModifiedEvent` for files with changed last-write timestamps
  - Emits `FileRemovedEvent` for deleted files
- Emits `EngineEventShutdown` if the watched directory is deleted
- Ignores non-regular files and files whose names start with a dot (`.`)

---

## Threading and Concurrency

- Runs `Watch()` method asynchronously using a thread pool
- Uses atomic flag to manage run state and ensure safe start/stop
- Polling interval controls scan frequency

---

## Events Emitted

- `FileAddedEvent`: new files detected
- `FileModifiedEvent`: existing files modified
- `FileRemovedEvent`: files deleted
- `EngineEventShutdown`: monitored directory removed, triggering shutdown request

---

## Dependencies

- Standard C++17 libraries: `<filesystem>`, `<chrono>`, `<atomic>`, `<future>`, `<thread>`
- Core singleton (`Core::g_Core`) for event dispatch and thread pool
- Event classes: `FileAddedEvent`, `FileModifiedEvent`, `FileRemovedEvent`, `EngineEvent`
- Logging macros (e.g., `LOG_APP_INFO`)

---

## Example Usage

```cpp
AIAssistant::FileWatcher watcher("/path/to/watch", std::chrono::milliseconds(500));
watcher.Start();

// ... at shutdown:
watcher.Stop();
```

---

## Limitations

- Polling-based; does not use OS-native file system event notifications
- Excludes hidden and non-regular files from monitoring

| `timestamp` | `int64_t` | Numeric timestamp parsed from the filename. |

---

Parses a filename and extracts `ProbFileInfo` if it matches the expected PROB file naming convention.

  `std::optional<ProbFileInfo>` containing parsed info if successful;  
  `std::nullopt` if filename is invalid or does not follow the PROB pattern.

  ```

  PROB_<id>_<timestamp>.output.txt (output file)
  ```

- Handle AI request lifecycle and chat message management.

# PythonEngine Class Documentation

`PythonEngine` is a C++ class that manages embedding and running Python scripts within an application. It provides thread-safe execution of Python hooks and workflow tasks with automatic handling of the Python Global Interpreter Lock (GIL). Designed for integration with AI assistants, it facilitates Python-scripted interactions, event handling, and task execution while ensuring proper lifecycle management of the Python interpreter.

`AIAssistant`

- Initializes a Python interpreter and loads a user-supplied Python script as a module.
- Redirects Python standard output and errors into the host application's logging.
- Supports asynchronous execution of lifecycle hooks (`OnStart`, `OnUpdate`, `OnEvent`, `OnShutdown`) via a worker thread.
- Allows executing user-defined Python workflow tasks with input, context, and output parameters.
- Converts custom C++ events into Python dictionaries to be passed to Python event hooks.
- Manages proper thread synchronization and clean shutdown of Python environment.

Destructor. Cleans up resources if still running.

Stops the Python engine cleanly by:  
- Enqueuing the `Shutdown` hook (if defined).

# TriggerEngine Class Documentation

Namespace: `AIAssistant`

---

## Overview

`TriggerEngine` manages trigger registration, evaluation, and firing to start workflow runs. It supports:

- **Auto triggers**: Fire once immediately when registered (if enabled).
- **Cron triggers**: Evaluate simple 5-field cron expressions periodically.
- **File-watch triggers**: Fire on file system events with debounce logic.
- **Manual triggers**: Fired explicitly by user request.

Trigger firing occurs by invoking a callback passed during construction.

> Does not parse workflow JSON; workflow triggers must be registered externally.

---

## Public API

### Construction

```cpp
TriggerEngine(TriggerCallback const& triggerCallback);
```
- `triggerCallback`: Called with `TriggerFiredEvent` when a trigger fires.

### Registration

- `AddAutoTrigger(workflowId, triggerId, isEnabled)`  
  Registers and fires immediately if enabled.

- `AddCronTrigger(workflowId, triggerId, expression, isEnabled)`  
  Registers cron trigger with a 5-field expression: minute hour day month weekday.  
  Supports only `"*"` or single integers in each field.

- `AddFileWatchTrigger(workflowId, triggerId, path, events, debounceMilliseconds, isEnabled)`  
  Watches `path` for specified `events` (`Created`, `Modified`, `Deleted`) with debounce interval.

- `AddManualTrigger(workflowId, triggerId, isEnabled)`  
  Registers manual trigger.

- `ClearWorkflowTriggers(workflowId)`  
  Removes all triggers for given workflow; reindexes file-watch triggers.

### Runtime

- `Tick(now)`  
  Evaluate cron triggers; fire and reschedule as needed.

- `NotifyFileEvent(path, fileEventType, now)`  
  Notify file event; fires matching file-watch triggers respecting debouncing.

- `FireManualTrigger(workflowId, triggerId)`  
  Fire manual trigger if exists and enabled.

---

## Types

### `FileEventType` (enum class)

- `Created`
- `Modified`
- `Deleted`

### `TriggerFiredEvent` (struct)

- `std::string m_WorkflowId`
- `std::string m_TriggerId`

Passed to the callback when a trigger fires.

---

## Key Implementation Details

- **CronExpression**: Minimal parser, accepts `"*"` or a single integer per field;  
  computes next fire time by checking minute increments up to one year ahead.

- **FileWatchTriggerInstance**: Supports exact and prefix path matching with normalized paths (`\` → `/` and no duplicate slashes).  

- Debounce ensures minimum interval between fires per trigger.

- File events processed via index map for exact path matches and by scanning for prefix matches.

- Manual triggers only fire if enabled and registered.

---

## Usage Example

```cpp
auto callback = [](const TriggerEngine::TriggerFiredEvent& e) {
    StartWorkflow(e.m_WorkflowId, e.m_TriggerId);
};

AIAssistant::TriggerEngine engine(callback);

engine.AddAutoTrigger("wf1", "auto1", true);
engine.AddCronTrigger("wf1", "cron1", "0 12 * * 1", true);
engine.AddFileWatchTrigger("wf1", "file1", "/var/log", {FileEventType::Modified}, 1000, true);
engine.AddManualTrigger("wf1", "manual1", true);

auto now = std::chrono::system_clock::now();
engine.Tick(now);
engine.NotifyFileEvent("/var/log/syslog", FileEventType::Modified, now);
engine.FireManualTrigger("wf1", "manual1");
```

## Thread Safety

No inherent thread safety guarantees; synchronize externally if needed.

---

## Description

`AIAssistant::ThreadPool` manages a pool of worker threads using `BS::thread_pool<>`. It allows asynchronous task submission, waiting for task completion, resizing the pool, and retrieving thread IDs. Task submission is protected by a mutex for thread safety.

Blocks the caller until all submitted tasks have finished executing.

Returns the number of currently active worker threads.

- Submits a task to be executed asynchronously.
- Thread-safe; mutex-guarded to allow concurrent calls.

# AIAssistant::EventQueue

Thread-safe queue for managing `Event` objects intended for consumption on the main thread.

---

## Overview

`EventQueue` stores `std::shared_ptr<Event>` instances in a synchronized queue. Multiple threads can safely add events via `Push()`, while the main thread retrieves events using `Pop()` or `PopAll()`.

---

## Public Types

- `using EventPtr = std::shared_ptr<AIAssistant::Event>;`  
  Shared pointer type alias for events.

---

## Public Methods

### `void Push(EventPtr event)`

Adds an event to the queue. Moves the event into the queue. Thread-safe.

### `EventPtr Pop()`

Removes and returns the front event. Returns `nullptr` if the queue is empty. Thread-safe.

### `std::vector<EventPtr> PopAll()`

Removes and returns all events as a vector. Intended for periodic main-thread batch processing. Thread-safe.

### `size_t Size()`

Returns the current number of events in the queue. Thread-safe.

---

## Thread Safety

All methods synchronize access using an internal mutex (`m_QueueAccessMutex`), preventing data races in multithreaded contexts.

---

## Usage Notes

- Worker threads push events.
- Main thread consumes events one-by-one (`Pop()`) or in batches (`PopAll()`).
- Shared pointers ensure safe shared ownership across threads.

---

## Example

```cpp
AIAssistant::EventQueue queue;

// Producer thread
queue.Push(std::make_shared<AIAssistant::Event>(/*...*/));

// Consumer (main) thread
auto event = queue.Pop();
if (event) { /* handle event */ }

auto events = queue.PopAll();
for (auto& e : events) { /* handle each event */ }

// Check queue size
size_t count = queue.Size();
```

1. Instantiate `KeyboardInput`.
2. Call `Start()` to begin listening for key presses.

4. Press `'q'` or `'Q'` to issue a shutdown request event.

# `AIAssistant::Log` Class Documentation

## Overview

`AIAssistant::Log` initializes and manages two `spdlog` loggers—`Engine` and `Application`—that output thread-safe, timestamped logs to `std::cout`. It supports integration with terminal UI frameworks by using an ostream sink compatible with stream redirection.

## Purpose

- Provide centralized, consistent logging for the engine and application components.
- Create and register two named loggers with `trace` level and immediate flush.
- Use a console sink with a fixed pattern (timestamp, logger name, level, message) without color codes.
- Enable redirection of `std::cout` for specialized terminal handling (e.g., ncurses).

## Usage

```cpp
AIAssistant::Log logSystem;
auto& engineLogger = logSystem.GetLogger();
engineLogger.info("Engine started");

auto& appLogger = logSystem.GetAppLogger();
appLogger.error("Application error");
```

## Configuration

- **Sink:** `spdlog::sinks::ostream_sink_mt` writing to `std::cout` with forced flush.
- **Pattern:** `[%Y-%m-%d %H:%M:%S.%e] [%n] [%l] %v`
- **Log Level:** `trace`
- **Flush on:** every `trace` message
- **Global Registration:** Registered with spdlog under `"Engine"` and `"Application"` names.

## Important

- The ostream sink relies on `std::cout`, which may be redirected externally for terminal UI integration.
- Pattern excludes colors to maintain compatibility with ncurses or similar systems.

## Public Interface

    spdlog::logger& GetAppLogger();   // Returns the Application logger

# TerminalLogStreamBuf Class Documentation

## Overview

`TerminalLogStreamBuf` is a custom `std::streambuf` subclass that captures streaming text output and simultaneously sends it to:

- A terminal interface managed by `TerminalManager`.
- A log file via a shared `std::ofstream`.

The class cleans each line by stripping ANSI escape sequences and discards empty or whitespace-only lines before dispatching.

---

## Declaration

```cpp
namespace AIAssistant {
    class TerminalLogStreamBuf : public std::streambuf { /* ... */ };
}
```

---

## Purpose

- Buffer incoming stream characters until newline.
- Remove ANSI escape codes from buffered lines.
- Filter out empty or whitespace-only lines.
- Enqueue cleaned lines to a terminal log queue (if provided).
- Write cleaned lines to a log file in a thread-safe manner.
- Handle line-flush operations on newline or explicit sync.

---

## Constructor

```cpp
TerminalLogStreamBuf(TerminalManager* terminalManager, std::shared_ptr<std::ofstream> fileLogger);
```

- `terminalManager`: Pointer to terminal manager for logging; may be `nullptr`.
- `fileLogger`: Shared pointer to an open output file stream; may be `nullptr`.

Initializes internal logging references.

---

## Key Member Functions

### `int overflow(int character) override`

- Buffers characters one by one.
- On newline (`'\n'`), flushes buffer via `sync()`.
- Returns not-EOF on EOF input to keep stream active.

### `int sync() override`

- Called to flush buffered content.
- Cleans buffer by removing ANSI escape sequences.
- Skips empty or whitespace-only lines.
- Sends cleaned line to terminal manager's log queue if available.
- Writes to log file with exclusive mutex lock if file is open.
- Clears internal buffer after flushing.

### `std::streamsize xsputn(const char* data, std::streamsize count) override`

- Appends input data to buffer.
- Flushes buffer if it ends in newline (auto sync).
- Returns number of characters processed.

---

## Utility

### `static std::string StripAnsi(const std::string& input)`

- Removes ANSI escape sequences starting with ESC `0x1B`.
- Escape sequences end on first alphabetic character (A-Z, a-z).
- Returns cleaned string without ANSI codes.

|----------------------------------|----------------------------------------|
| `TerminalManager* m_TerminalManager` | Terminal manager for UI log dispatch    |
| `std::string m_Buffer`            | Buffered characters until line flush   |

# TerminalManager Class Documentation

Namespace: `AIAssistant`

---

## Overview

The `TerminalManager` class provides a terminal-based UI manager for displaying logs and status information concurrently in separate window sections. It supports dynamic resizing, thread-safe log enqueuing, and customizable status display via user-provided callbacks.

The class uses the `pdcurses` library for terminal manipulation, manages multiple windows for log and status output, and ensures seamless rendering.

---

## Public Types

- **StatusLinesCallback**  
  A callback type: `std::function<void(std::vector<std::string>& lines, int maxWidth)>`  
  Used to provide the status text lines to render, given the maximum width of the status window.

- **StatusHeightCallback**  
  A callback type: `std::function<int(int totalRows)>`  
  Used to specify the height in rows of the status section based on the total terminal rows.

---

## Constructor and Destructor

- **TerminalManager()**  
  Constructs a new `TerminalManager`. Does not initialize the terminal UI.

- **~TerminalManager()**  
  Destructor. Calls `Shutdown` to clean up UI windows and end the terminal session if initialized.

---

## Public Member Functions

- **void Initialize()**  
  Initializes the terminal environment and windows:  
  - Sets locale  
  - Configures terminal input modes  
  - Creates the log and status windows based on terminal size  
  - Applies color theme if available  
  - Marks the terminal manager as initialized

- **void Shutdown()**  
  Cleans up the terminal UI:  
  - Deletes all created windows  
  - Ends the curses mode  
  - Marks the terminal manager as uninitialized

- **void Render()**  
  Main per-frame rendering method:  
  - Handles window resizing if terminal size changes  
  - Drains and displays pending log lines enqueued from other threads  
  - Calls registered status lines callback to update status window content

- **void RenderPaused(int counter)**  
  Similar to `Render()`, but displays a paused message in the log window along with an integer counter. It still renders the status section.

- **void EnqueueLogLine(const std::string& line)**  
  Thread-safe method to add a log line to the pending queue for later rendering. Logs are displayed in the log window sequentially.

- **void SetStatusCallbacks(StatusLinesCallback statusLinesCallback, StatusHeightCallback statusHeightCallback)**  
  Registers callbacks to customize the status window:  
  - `statusLinesCallback` provides the lines to display in the status window  
  - `statusHeightCallback` provides the desired height in rows of the status section  
  Causes terminal windows to be recreated if needed to accommodate new status height.

---

## Behavior Details

- **Window Layout**:  
  The terminal window is split vertically into sections:  
  1. Log Header (1 row)  
  2. Log Content (dynamic height)  
  3. Status Header (1 row)  
  4. Status Content (dynamic height as per callback)  

- **Color Theme**:  
  Attempts to set a custom green color close to "#02a414" if terminal supports color changes. Otherwise, falls back to default green color pair.

- **Thread Safety**:  
  The log lines queue is protected by a mutex, allowing log lines to be enqueued safely from multiple threads.

- **Resizing**:  
  On terminal resize, windows are recreated and headers are redrawn. The status section height is adjusted based on the status height callback.

- **Paused Mode**:  
  The `RenderPaused` method clears and shows a paused notice in the log window, including a counter value toggled externally.

---

## Example Usage

```cpp
AIAssistant::TerminalManager terminalManager;

terminalManager.SetStatusCallbacks(
    [](std::vector<std::string>& lines, int maxWidth) {
        lines = { "Status Line 1", "Status Line 2" }; // example status text
    },
    [](int totalRows) -> int {
        return 3; // fixed 3 rows for status section
    }
);

terminalManager.Initialize();

terminalManager.EnqueueLogLine("Application started.");

while (running)
{
    terminalManager.Render();
    // application logic ...
}

terminalManager.Shutdown();
```

---

## Notes

- Must call `Initialize()` before any other method except constructor/destructor.
- Call `Shutdown()` before destruction to restore terminal state.
- Callbacks can be changed dynamically and will re-layout the terminal accordingly.
- Requires terminal supporting curses (for example, Linux terminal, Windows with pdcurses).
- Designed for efficient and thread-safe log display alongside dynamic status info.

# AIAssistant::Application

Abstract base class defining the interface for an application within the AI Assistant framework.

## Description  
Provides mandatory lifecycle methods for applications: startup, update, event handling, shutdown, and status checking.

## Methods  

- **virtual ~Application() = default;**  
  Virtual destructor for proper cleanup in derived classes.

- **virtual void OnStart() = 0;**  
  Initialize resources or state at application start.

- **virtual void OnUpdate() = 0;**  
  Update application logic regularly (e.g., per frame).

- **virtual void OnEvent(std::shared_ptr<Event>&) = 0;**  
  Process incoming events.

- **virtual void OnShutdown() = 0;**  
  Cleanup resources during shutdown.

- **virtual bool IsFinished() const = 0;**  
  Indicates if the application has completed execution.

## Usage  
Inherit and implement all pure virtual methods to define the application behavior in the AI Assistant environment.

## Overview

`FileCategorizer` manages a collection of files by categorizing them into predefined groups based on filename patterns, file content, and attributes. The class is designed to efficiently filter and classify files relevant for AI processing or human interaction, ignoring binaries, large files, or irrelevant file types.

### `CategorizedFiles`

Contains multiple `TrackedFiles` groups by category:

- `m_Settings`
- `m_Context`
- `m_Tasks`
- `m_Provider`
- `m_Requirements`
- `m_Subfolders`
- `m_Ignored`

- `Settings`

- `Ignored`

## Public Methods

### `fs::path const AddFile(fs::path const& filePath)`

Adds a file to the appropriate category based on the `Categorize` function. Creates a new `TrackedFile` marked as modified. The category's modified counter is incremented. Returns the input `filePath`.

---

### `fs::path const RemoveFile(fs::path const& filePath)`

Removes the specified file from all categories if present. Updates counters and dirty flags accordingly. Returns the input `filePath`.

---

### `fs::path const ModifyFile(fs::path const& filePath)`

Checks if the file’s content has changed since last tracked. If changed, marks it modified and increments the modification counter. Ignores files categorized as `Ignored`. Returns the input `filePath`. Logs a warning if the file is not tracked.

---

Returns a reference to the internal `CategorizedFiles` structure containing all tracked files grouped by category.

---

Prints all tracked files grouped by category to the standard output for debugging or review.

---

## Private Methods

### `FileCategory Categorize(fs::path const& filePath) const`

Determines a file’s category based on:

- Directory status → `SubFolder`
- File name prefixes (`STNG`, `CNTX`, `TASK`, `PROV`) → maps to `Settings`, `Context`, `Task`, or `Provider`
- `.output` suffix or `.output.txt` files → `Ignored`
- `.prob` filename parsing and timestamp check for stale detection → `Ignored` or `Requirement`
- Magic number inspection identifying common binary formats (ZIP, PDF, images, executables):
  - Known binaries → `Ignored`
  - Document types (PDF/Office) skipped silently → `Ignored`
- Text content heuristics based on printable character ratio → binary-like files ignored
- File size exceeding configured limit → ignored, with a `.output.txt` message file created
- Default → `Requirement` category

---

### `void RemoveFromFiles(TrackedFiles& files, fs::path const& path)`

Removes the file from the provided `TrackedFiles` container, decrements counters if modified, and sets the dirty flag.

---

## Usage Notes

- Files tracked as modified are efficiently counted per category to facilitate selective processing.
- Categorization excludes binary, unreadable, oversized, or stale files to optimize resource usage.
- The class uses file content inspection and filename heuristics to decide categorization.
- Supports dynamic tracking: addition, removal, and modification detection.

The `FileCategorizer` class provides a robust system for effectively grouping, tracking, and filtering files within an AI assistant environment. It automates file classification, modification tracking, and exclusion of irrelevant or problematic files, ensuring optimized input data for AI or human workflows.

# FileWatcher Class Documentation

## Overview  
`FileWatcher` monitors a directory and its subdirectories for file changes, including additions, modifications, and deletions. It reports these changes by pushing events into the system event queue asynchronously.

## Namespace  
`AIAssistant`

## Purpose  
To provide an efficient, asynchronous way to track filesystem changes at specified intervals and notify interested components via events.

---

## Public Interface

### Constructor  
```cpp
explicit FileWatcher(const fs::path& pathToWatch, std::chrono::milliseconds interval = 100ms);
```
- **pathToWatch**: Directory path to monitor recursively.  
- **interval**: Time interval for polling filesystem changes (default 100ms).

### Destructor  
```cpp
~FileWatcher();
```
Stops monitoring and cleans up resources.

### Methods

#### Start  
```cpp
void Start();
```
Starts the monitoring process on a background thread. No effect if already running.

#### Stop  
```cpp
void Stop();
```
Stops monitoring and waits for the background thread to finish. No effect if not running.

---

## Private Methods

### `void Watch()`  
Main monitoring loop that:
- Performs an initial scan and dispatches `FileAddedEvent` for existing files.  
- Periodically rescans to detect and dispatch events for:  
  - New files (`FileAddedEvent`),  
  - Modified files (`FileModifiedEvent`),  
  - Removed files (`FileRemovedEvent`).  
- Dispatches `EngineEventShutdown` if the root directory is deleted.

### `bool IsValidFile(fs::directory_entry const& entry)`  
Returns true if the entry is a regular file and its filename does not start with '.' (ignores hidden/temporary files).

---

## Data Members  

- `m_PathToWatch`: Path being monitored.  
- `m_Interval`: Polling interval.  
- `m_Running`: Atomic boolean indicating watch state.  
- `m_WatchTask`: Future representing the asynchronous watch task.

---

## Event System Integration  

- Uses `Core::g_Core->PushEvent` to enqueue:  
  - `FileAddedEvent` on new files,  
  - `FileModifiedEvent` on file updates,  
  - `FileRemovedEvent` on deletions,  
  - `EngineEventShutdown` if watching directory is removed.

---

## Usage Summary

1. Create `FileWatcher` with a target directory and optional interval.  
2. Call `Start()` to begin asynchronous monitoring.  
3. Receive events via the system event queue.  
4. Call `Stop()` to end monitoring safely.

---

## Additional Notes

- Monitoring is recursive over all subdirectories.  
- Uses file last write timestamps for change detection (polling-based).  
- Ignores files starting with '.' to exclude hidden/temp files.  
- Relies on a thread pool from `Core::g_Core` for background execution.  
- Thread-safe control via atomic flags and futures.

---

## Example

```cpp
AIAssistant::FileWatcher watcher("/path/to/watch", std::chrono::milliseconds(200));
watcher.Start();
// ... application logic ...
watcher.Stop();
```

---

This class facilitates responsive file change detection for both human users and AI components through an event-driven, asynchronous design.

# TrackedFile Class Documentation

## Overview
`TrackedFile` manages a file on disk by tracking its content changes and categorizing it. It enables efficient detection of modifications for use in human or AI-assisted workflows.

---

## Namespace
`AIAssistant`

---

## Class: `TrackedFile`

### Purpose
- Tracks a file's on-disk content changes using hash comparison.
- Stores file path and category metadata.
- Provides thread-safe access to file content and modification status.

---

## Public Interface

### Constructor
```cpp
TrackedFile(fs::path const& path, FileCategory fileCategory);
```
- Initializes tracking for the file at `path` with the specified `fileCategory`.
- Computes initial content hash.
- Marks the file as modified.

---

### Methods

#### `bool IsModified() const`
- Returns whether the file is currently marked as modified.

#### `fs::path const& GetPath() const`
- Returns the tracked file's filesystem path.

#### `void MarkModified(bool modified = true)`
- Sets the modification status of the file.
- Default sets modified to `true`.

#### `std::string GetContent()`
- Returns the file content as a string.
- Resets modification detection is not automatic on this call.
- Thread-safe file reading.
- Logs a warning if file cannot be opened.

#### `FileCategory GetCategory() const`
- Returns the `FileCategory` associated with the file.

#### `bool CheckIfContentChanged()`
- Checks if content changed on disk by comparing new hash with the last stored hash.
- Updates the stored hash if changed.
- Returns `true` if content changed, else `false`.
- Thread-safe.

---

## Private Methods

### `std::string ComputeFileHash() const`
- Reads the file content in binary mode.
- Computes and returns a SHA-256 hash string if OpenSSL is available.
- Falls back to a lightweight `std::hash` of the content string if OpenSSL unavailable.
- Returns empty string if the file cannot be opened.

---

## Data Members

- `fs::path m_Path`  
  The file system path of the tracked file.

- `FileCategory m_FileCategory`  
  The category/label assigned to the file.

- `std::atomic<bool> m_Modified`  
  Flag indicating if the file is marked as modified. Initialized to `true`.

- `std::string m_LastHash`  
  Stores last computed hash of the file content for change detection.

- `mutable std::mutex m_Mutex`  
  Mutex to synchronize access to file reading and hash computation.

---

## Usage Summary
- Create a `TrackedFile` instance for a file and category.
- Use `IsModified()` to query if file changed since last check.
- Use `CheckIfContentChanged()` to refresh and detect file changes.
- Call `GetContent()` to retrieve current file contents safely.
- Use `MarkModified()` to manually set modification status if needed.

---

## Dependency
- Requires OpenSSL `<openssl/sha.h>` for SHA-256 hashing if available.
- Falls back to `std::hash` otherwise.
- Uses standard C++ filesystem and threading utilities.

---

## Thread Safety
- File access and hash calculations are protected by a mutex.
- Modification flag uses atomic operations for safe concurrent reads/writes.

# JarvisAgent Class Documentation

## Overview

`JarvisAgent` is a central application class in the AIAssistant namespace, responsible for orchestrating multiple subsystems including file watching, web serving, Python scripting, AI requests, workflows, and session management. It integrates workflows with triggers, handles events including file system changes and Python crashes, and manages task execution.

## Class Responsibilities

- Initialize and start core components: file watcher, web server, Python engine, AI request pool, workflows, and triggers.
- Register internal tasks and workflow task executors.
- Maintain session managers for request, setting, and task state machines.
- Handle event dispatching for engine events, file system events, Python crashes, and AI output files.
- Update subsystems every frame or tick, including sessions, triggers, AI requests, and workflows.
- Manage shutdown procedures to gracefully stop and cleanup subsystems.
- Provide access to key subsystems and state (e.g., startup timestamp, internal task registry).

## Key Public Methods

### Creation and Lifecycle

- `static std::unique_ptr<Application> Create()`  
  Factory method to instantiate a `JarvisAgent`.

- `void OnStart()`  
  Initialize components, register tasks, start services, and load workflows.

- `void OnUpdate()`  
  Called each frame to update sessions, clean messages, process triggers and workflows, and broadcast updates.

- `void OnEvent(std::shared_ptr<Event>& eventPtr)`  
  Handle incoming events, including engine shutdown, file system events, Python crashes, and AI output files, forwarding them to appropriate subsystems.

- `void OnShutdown()`  
  Gracefully stop and cleanup all started components and subsystems.

  Returns pointer to the chat message pool.

  Returns the application startup time.

  Returns the application startup time as nanoseconds since epoch.

- `StatusRenderer& GetStatusRenderer()`  
  Access the status renderer for building UI status lines.

- `PythonEngine* GetPythonEngine()`  
  Access the embedded Python engine.

- `WorkflowRegistry* GetWorkflowRegistry()`  
  Access the loaded workflow registry.

- `AiRequestPool* GetAiRequestPool() const`  
  Access the AI request pool that manages AI call lifecycles.

- `WorkflowRuntimeManager* GetWorkflowRuntimeManager() const`  
  Access the workflow runtime manager handling active workflow executions.

- `IInternalTaskRegistry* GetInternalTaskRegistry()`  
  Access internal task registry for registering or querying internal tasks.

## Internal Methods

- `void InitializeWorkflows()`  
  Loads workflows from disk, validates them, registers task executors, sets up runtime and trigger engine, and binds triggers.

  Checks shutdown conditions (currently listens for shutdown event, typically CTRL+C).

## Member Variables

  Indicates if shutdown has been requested.

  Utility for rendering dynamic status lines in terminal.

## Event Handling Details

- Handles engine shutdown signals to mark the app finished.
- Processes file system events (added, modified, removed) forwarding them to the trigger engine except for suppressed startup events.
- Routes PROB file output events to AI request pool or chat message pool, ignoring stale files.
- Handles Python crash events by stopping the embedded Python engine.
- Routes remaining file events to corresponding session managers based on file path.

## Usage

`JarvisAgent` is typically instantiated and managed by the core application engine. Its lifecycle methods (`OnStart`, `OnUpdate`, `OnEvent`, `OnShutdown`) integrate with the main event loop and system signals to run an AI-assistant platform capable of responding to workflows and external events.

# AIAssistant::QueryParser Documentation

## Overview

`QueryParser` is a C++ class that parses Lucene-style query strings into an Abstract Syntax Tree (AST) and evaluates these queries against documents represented as key-value string maps. It supports Boolean logic (AND, OR, NOT), exact and wildcard field matches, range queries, and negation shorthand.

---

## Query Language Grammar

- `query`      := `orExpr`  
- `orExpr`     := `andExpr` ("OR" `andExpr`)*  
- `andExpr`    := `unaryExpr` ("AND" `unaryExpr`)*  
- `unaryExpr`  := "NOT" `unaryExpr` | "-" `fieldExpr` | "(" `query` ")" | `fieldExpr`  
- `fieldExpr`  := FIELD ":" ( `rangeExpr` | `value` )  
- `rangeExpr`  := "[" `value` "TO" `value` "]" | "{" `value` "TO" `value` "}"  
- `value`      := WORD | QUOTED_STRING  

**Notes**:  
- A value ending with `*` denotes a prefix wildcard match.  
- `-field:value` is shorthand for `NOT field:value`.  

---

## Core Types

### QueryNode

AST node representing parsed query components.

- `QueryNodeType` enum values:  
  - `And`, `Or`, `Not` for Boolean logic nodes  
  - `FieldMatch` for exact or wildcard field-value matching  
  - `FieldRange` for inclusive or exclusive range queries  

- Data fields depend on node type:  
  - `And` / `Or`: vector of child nodes  
  - `Not`: single child node  
  - `FieldMatch`: field name, value, and wildcard flag  
  - `FieldRange`: field name, low/high bounds, inclusivity flags  

### QueryDocument

- Alias for `std::unordered_map<std::string, std::string>`  
- Represents documents as field-value maps for query matching.  

---

## Public API

### `std::unique_ptr<QueryNode> Parse(const std::string& queryString, std::string& errorMessage) const`

- Parses a Lucene-style query string into an AST.  
- Returns `nullptr` and sets `errorMessage` on failure.  
- Performs tokenization and recursive descent parsing with support for grouping, negation, wildcards, and ranges.

### `static bool Matches(const QueryNode& node, const QueryDocument& doc)`

- Evaluates whether `doc` matches the query represented by `node`.  
- Returns `true` if the document satisfies the query conditions, `false` otherwise.  
- Supports evaluation of Boolean expressions, exact and prefix matches, and range queries including numeric and lexicographic comparisons.

---

## Implementation Details

- **Tokenizer**: Splits input into tokens such as keywords, words, quoted strings, operators, braces, and parentheses.  
- **Parser**: Uses recursive descent to apply grammar rules to tokens and build an AST.  
- **Evaluator**: Recursively matches AST nodes against document fields:  
  - Exact matches compare string equality.  
  - Wildcard matches check prefix equality.  
  - Range matches compare numeric values first, falling back to lexicographic comparison.  
  - Boolean nodes combine child evaluations with logical semantics.

---

## Typical Usage

1. Call `Parse` with a query string to get an AST.  
2. On success, call `Matches` with the AST and a document to check if the document satisfies the query.  
3. Use error messages to diagnose parse failures.

---

## Summary

`AIAssistant::QueryParser` enables efficient parsing and evaluation of sophisticated search queries against simple key-value documents using a rich, Lucene-style language with support for wildcards, Boolean logic, field ranges, and negations.

# TaskFreshnessChecker

`TaskFreshnessChecker` provides Makefile-style up-to-date checks for tasks within a workflow, ensuring efficient task execution by verifying task outputs relative to inputs and dependencies.

## Overview

The class verifies whether a task is "up to date" by checking:

- All declared output files exist.
- The oldest output timestamp is greater than or equal to the newest input or upstream output timestamp.
- Inputs include both the task's declared inputs and outputs from all upstream dependent tasks (transitive closure).

## Public Interface

### `struct ResolvedPaths`

Represents resolved input and output filesystem paths of a task.

- `std::vector<std::filesystem::path> m_InputPaths` — Declared input paths.
- `std::vector<std::filesystem::path> m_OutputPaths` — Declared output paths.

### `using ResolveOutputPathsFn`

Signature of a user-provided callback function to resolve output paths by task ID:

```cpp
bool(std::string const& taskId, std::vector<std::filesystem::path>& outPaths);
```

Returns `true` on success; `outPaths` is populated with paths.

### `bool IsTaskUpToDate(...) const`

Determines if the task is up to date according to Makefile-style freshness rules.

**Parameters:**

- `WorkflowDefinition const& workflowDefinition` — The overall workflow description including task definitions.
- `std::string const& taskId` — Identifier of the task to check.
- `ResolvedPaths const& resolvedPaths` — Contains input and output paths for the task.
- `ResolveOutputPathsFn const& resolveOutputPaths` — Callback to resolve outputs of dependent tasks.
- `std::filesystem::path* comparedInputPath` (optional) — Outputs the latest input or upstream output path compared.
- `std::filesystem::path* comparedOutputPath` (optional) — Outputs the earliest output path compared.

**Returns:**  
`true` if the task is up to date; `false` otherwise.

## Internal Logic

1. **Input Timestamps:**  
   Checks existence and modification times of declared input files.

2. **Upstream Outputs:**  
   Recursively collects outputs and their timestamps from all upstream dependencies.

3. **Output Timestamps:**  
   Checks existence and modification times of declared output files.

4. **Freshness Comparison:**  
   Compares the newest input/upstream output timestamp against the oldest output timestamp. If outputs are newer or equal, the task is fresh.

## Private Methods

### `bool CollectUpstreamOutputTimes(...) const`

Recursively collects modification times of all upstream task outputs.

**Parameters:**

- `workflowDefinition` — Workflow with all tasks.
- `taskId` — Current upstream task ID.
- `visitedTasks` — Set to avoid cycles.
- `outTimes` — Accumulates timestamps and paths.
- `resolveOutputPaths` — Callback to resolve task output paths.

**Returns:**  
`true` if all upstream outputs exist and are readable; `false` otherwise.

## Usage Context

This class is typically used in workflow engines or build systems where tasks have dependencies and output files. It enables efficient incremental builds or executions by skipping tasks whose outputs are newer than inputs and dependencies’ outputs.

## Notes

- Tasks with no outputs are always considered not up to date.
- Errors accessing file metadata or missing files cause the task to be considered not up to date.
- Paths are normalized lexically before checks.
- Debug logging is integrated to trace freshness checks and possible failures.

# AIAssistant Template Engine Documentation

## Overview

The `AIAssistant` namespace provides a unified, flexible template expansion engine for processing strings with `{{...}}` placeholders. It supports key-based substitutions using inputs, outputs, environment variables, and named slots, enabling dynamic generation of command lines, scripts, or textual content for both humans and AI systems.

## Key Components

### TemplateMode

```cpp
enum class TemplateMode {
    Strict,
    Lenient
};
```

- **Strict:** Unknown keys or invalid indices cause expansion failure and return an error message. Suitable for shell tasks and strict validation.
- **Lenient:** Unknown keys simply expand to empty strings. Useful for AI calls and templates where missing keys are allowed.

### TemplateContext

```cpp
struct TemplateContext {
    std::vector<std::string> const* m_FileInputs = nullptr;
    std::vector<std::string> const* m_FileOutputs = nullptr;
    std::unordered_map<std::string, std::string> const* m_InputValues = nullptr;
    std::unordered_map<std::string, std::string> const* m_EnvVariables = nullptr;
};
```

Holds all data sources used for template expansion:

- `m_FileInputs`: Pointer to a list of input filenames.
- `m_FileOutputs`: Pointer to a list of output filenames.
- `m_InputValues`: Pointer to key-value mappings for named slots and cross-references.
- `m_EnvVariables`: Pointer to environment variables accessible by name.

### ExpandTemplate

```cpp
bool ExpandTemplate(std::string const& templateText, TemplateContext const& context, TemplateMode mode,
                    std::string& expandedOut, std::string& errorMessage);
```

Expands the `templateText` by replacing all `{{key}}` placeholders based on `context` and `mode`.

#### Parameters

- `templateText`: Input string containing placeholders.
- `context`: Data sources for resolving placeholders.
- `mode`: Expansion mode (`Strict` or `Lenient`).
- `expandedOut`: Output parameter containing the expanded string on success.
- `errorMessage`: Output parameter set on error (only in `Strict` mode).

#### Returns

- `true` on successful expansion.
- `false` on failure (e.g., unknown keys or invalid indices in `Strict` mode).

#### Supported Placeholder Patterns

- `{{inputs}}`: Space-separated list of all input files.
- `{{outputs}}`: Space-separated list of all output files.
- `{{input[N]}}`: Zero-based N-th input file.
- `{{output[N]}}`: Zero-based N-th output file.
- `{{slot.NAME}}`: Lookup `NAME` in input values (named slots).
- `{{env.NAME}}`: Lookup environment variable `NAME`.
- `{{inputs.NAME}}`: Lookup `NAME` as an input value (dataflow cross-reference).
- `{{anything_else}}`: Bare lookup in input values.

#### Error Handling

- Missing or malformed placeholders cause errors in `Strict` mode with clear messages.
- Placeholders with out-of-range indices or unknown keys cause failure in `Strict` mode.
- In `Lenient` mode, unknown keys or malformed placeholders expand to empty strings or literal text without error.

## Usage Notes

- Designed for seamless integration with build systems, AI prompt generation, and shell command preparation.
- Provides robust handling of various dynamic data sources.
- Supports both strict validation and lenient fallback behavior.

# WorkflowRuntimeManager Class Documentation

## Overview
`WorkflowRuntimeManager` is a tick-based workflow execution manager designed to coordinate and manage asynchronous workflow runs. It orchestrates task execution, monitors task states, handles retries, and supports per-item task fan-out. The class enables non-blocking, concurrent processing suitable for integration into event-driven main loops, such as within AI agents.

## Responsibilities
- Managing lifecycle of workflow runs: enqueuing, starting, updating, and cancellation.
- Tracking active and completed workflow runs with thread-safe access.
- Asynchronously executing workflow tasks with retry and freshness checks.
- Integrating external AI request completions and handling deferred completions.
- Supporting per-item workflows through filter evaluation and fan-out child tasks.
- Cleaning workflow-generated output artifacts safely without touching source files.

## Usage
- Use `Start()` and `Stop()` to control runtime manager state.
- Enqueue runs via `EnqueueWorkflowRun`, `EnqueueWorkflowRunAndGetRunId`, or `EnqueueWorkflowRunWithContextAndGetRunId`.
- Call `Update()` periodically (e.g. main event loop) to advance workflows and process task completions.
- Query workflow state with `TryGetLastRun`, `TryGetActiveRun`, `TryGetRunById`, and snapshots (`GetActiveRunsSnapshot`, `GetLastRunsSnapshot`).
- Request cancellation via `RequestCancelRun`.
- Clean workflow outputs with `CleanWorkflow`.

## Public Methods

### void Start()
Starts the workflow runtime manager, enabling processing of workflow runs.

### void Stop()
Stops the runtime manager immediately, clearing all pending and active runs.

### void EnqueueWorkflowRun(const std::string& workflowId)
Enqueues a workflow run by workflow ID. A run ID is generated internally.

### std::string EnqueueWorkflowRunAndGetRunId(const std::string& workflowId)
Enqueues a workflow run by workflow ID and returns the assigned run ID.

### std::string EnqueueWorkflowRunWithContextAndGetRunId(const std::string& workflowId, const std::string& runId, const ContextMap& context)
Enqueues a workflow run with a specified run ID and context, generating a run ID if empty. Returns the assigned run ID.

### void Update()
Advances the workflow runtime state by processing active runs, tasks, AI completions, and dispatching new tasks. Must be called periodically to drive progress.

### void SetRegistry(const WorkflowRegistry* workflowRegistry)
Sets the workflow registry used to resolve workflow definitions.

### bool TryGetLastRun(const std::string& workflowId, WorkflowRun& outRun) const
Retrieves the last completed run for given workflow ID. Returns `true` if found.

### bool TryGetActiveRun(const std::string& runId, WorkflowRun& outRun) const
Retrieves an active run by its run ID. Returns `true` if found.

### bool RequestCancelRun(const std::string& runId)
Requests cancellation of an active run by run ID. Returns `true` if cancellation requested successfully.

### bool TryGetRunById(const std::string& runId, WorkflowRun& outRun) const
Finds a run by run ID among active and last completed runs. Returns `true` if found.

### std::vector<WorkflowRun> GetActiveRunsSnapshot() const
Returns a thread-safe snapshot copy of all active workflow runs.

### std::unordered_map<std::string, WorkflowRun> GetLastRunsSnapshot() const
Returns a thread-safe snapshot copy of the last completed runs keyed by workflow ID.

### bool CleanWorkflow(const std::string& workflowId, std::string& outErrorMessage)
Deletes output artifacts produced by the specified workflow. Returns `true` on success; on failure, returns `false` and populates `outErrorMessage`. Source or input files are never deleted.

## Internals and Implementation Details

- **Task Execution:** Tasks are run asynchronously on a worker thread pool using `ExecuteTaskOnWorker()`. Tasks handle retries based on configured `RetryPolicy`.
- **Task States:** Task states progress through `Pending`, `Ready`, `Running`, `Succeeded`, `Skipped`, `Failed`, and `WaitingExternal`. Terminal states are succeeded, skipped, or failed.
- **Per-Item Fan-Out:** Supports `PerItem` mode tasks where a filter defines multiple items. Task execution is fanned out into child instances (`taskId#index`). Filter evaluation is dispatched and completed asynchronously.
- **Freshness Checking:** Skips task execution if input/output freshness checks pass, populating skipped outputs if possible.
- **Cancellation:** Cooperative cancellation stops new work dispatch and marks pending/waiting tasks as skipped.
- **AI Completion Integration:** Supports external AI request completions which update task state, handling deferred completions if direct application is not immediately possible.
- **Thread Safety:** Access to shared state uses mutex locking for internal consistency.

## Private Types

- **TaskExecutionResult:** Represents the result of a single task execution attempt.
- **FilterEvalResult:** Holds results from filter evaluation in per-item fan-out.
- **PendingRun:** Represents a run queued but not yet started.
- **ActiveRun:** Bundles workflow definition, running state, active task futures, per-item fan-out structures, and cancellation flag.

## Notes
- Designed not to block main thread, suitable for integration into agent update loops.
- Supports concurrent runs and tasks with controlled retry and failure semantics.
- Logs workflow and task state changes extensively for debugging and audit trails.
- Cleaning workflow outputs ensures no interference with active runs and safely removes only generated artifacts.

   - Encrypted keys file decrypted with a master password from `JARVIS_MASTER_PASSWORD` environment variable.

   - Environment variables for API keys (backward compatibility).

8. Creates the Jarvis AI application and triggers its lifecycle methods:
   - `OnStart` to initialize.
   - Runs the engine with the AI application instance.

Namespace: `AIAssistant`

---

## Overview

`ConfigParser` is a C++ class designed to parse and validate a JSON configuration file for an AI assistant engine. It reads configuration fields from a JSON file, verifies their types, populates an `EngineConfig` structure, tracks config parsing state, and supports multiple API interfaces configuration.

Represents the parsing status.

- `ConfigOk`: Configuration parsed successfully.
- `ParseFailure`: Parsing failed due to invalid JSON.

- `FileFormatFailure`: Required fields missing or invalid in the config.

### Struct: `EngineConfig`

Holds all configurable parameters for the engine, including API interface details.

#### Enum: `InterfaceType`
Defines supported API interface types.

- `API1` (0)
- `API2`
- `NumAPIs`
- `InvalidAPI`

#### Struct: `ApiInterface`
Represents a single API interface configuration.

- `m_Name` (string): Interface name.
- `m_Description` (string): Optional description.
- `m_Url` (string): API endpoint URL.
- `m_Model` (string): Model identifier.
- `m_KeyName` (string): Key name used for authentication.
- `m_InterfaceType` (InterfaceType): Interface type enum.

---

## Public Methods

### `ConfigParser(std::string const& filepathAndFilename)`
Constructor. Initializes the parser with the path to the configuration file.

### `~ConfigParser()`
Destructor.

### `State GetState() const`
Returns the current parsing state.

### `State Parse(EngineConfig& engineConfig)`
Parses the JSON configuration at the provided file path into the supplied `engineConfig`.

- Resets `engineConfig` fields.
- Validates file existence and format.
- Parses JSON fields into `engineConfig`.
- Checks required fields (`queue folder` and `url`).
- Logs errors and parsing information.
- Returns final parsing `State` value.

### `bool ConfigParsed() const`
Returns `true` if the configuration was parsed successfully (`State::ConfigOk`).

---

## Private Methods

### `void ParseInterfaces(simdjson::ondemand::array jsonArray, EngineConfig& engineConfig, FieldOccurances& fieldOccurances)`
Parses the `"API interfaces"` JSON array into `engineConfig.m_ApiInterfaces`.

- Iterates each interface object.
- Extracts and validates keys: `name`, `description`, `key_name`, `url`, `model`, `API`.
- Auto-generates `m_Name` if missing based on URL domain, model, and API type.
- Updates field occurrence counters.

### `static std::string EngineConfig::GenerateInterfaceName(std::string const& url, std::string const& model, std::string const& apiType)`
Generates a unique interface name from a URL domain, model, and API type string.

- Extracts domain from URL.
- Concatenates domain, model, and apiType separated by slashes.

---

## Internal Data Members

- `State m_State`: Current parser state.
- `std::string m_ConfigFilepathAndFilename`: Path to the configuration file.

---

## Additional Details

- Uses the `simdjson` library for fast JSON parsing.
- Uses assertions (`CORE_ASSERT`) to validate JSON types.
- Logs parsing progress and errors via `LOG_CORE_INFO`, `LOG_CORE_ERROR`, and `LOG_CORE_WARN`.
- Resets the `EngineConfig` object before parsing to ensure a clean state.
- Requires `"queue folder"` and `"url"` fields to mark the config as valid.
- Supports multiple API interfaces with detailed configuration.
- Default values exist for some fields, e.g., `m_KeysFilePath` = `"keys.json.enc"`, `m_MaxFileSizekB` = 20.

---

## Usage

1. Instantiate a `ConfigParser` with a path to a config JSON file.
2. Create an uninitialized `EngineConfig` instance.
3. Call `Parse()` to populate the `EngineConfig`.
4. Use `GetState()` or `ConfigParsed()` to verify success.
5. Access `EngineConfig` fields as needed.

This class facilitates robust, efficient loading of AI assistant configuration with detailed error handling and logging.

# AIAssistant::KeyEncryption

AES-256-GCM encryption and decryption utility with PBKDF2 key derivation for secure handling of JSON plaintexts.

---

## Overview

This class provides methods to encrypt and decrypt JSON strings securely using AES-256-GCM symmetric encryption. It derives encryption keys from a master password using PBKDF2-HMAC-SHA256 with a random salt. The encrypted output includes a header, salt, IV, ciphertext, and an authentication tag to ensure data integrity and confidentiality.

---

## File Format

- **4 bytes:** Magic `"JKEY"`
- **1 byte:** Version (`0x01`)
- **16 bytes:** Salt (random, for key derivation)
- **12 bytes:** IV (random, for AES-GCM)
- **Variable:** Ciphertext (encrypted JSON)
- **16 bytes:** GCM authentication tag

---

## Constants

- `MAGIC`: `"JKEY"` magic bytes
- `VERSION`: 1
- `SALT_SIZE`: 16 bytes
- `IV_SIZE`: 12 bytes
- `TAG_SIZE`: 16 bytes
- `HEADER_SIZE`: 33 bytes (magic + version + salt + IV)
- `PBKDF2_ITERATIONS`: 100,000 iterations
- `KEY_SIZE`: 32 bytes (AES-256)

---

## Public Methods

### `static std::vector<uint8_t> Encrypt(const std::string& plaintext, const std::string& masterPassword)`

Encrypts a JSON plaintext string using a master password.

- Generates a random salt and IV.
- Derives a 256-bit AES key using PBKDF2-HMAC-SHA256 with the salt and master password.
- Encrypts plaintext with AES-256-GCM.
- Constructs output blob: header + ciphertext + 16-byte GCM tag.
- Returns the full encrypted blob as a vector of bytes.
- Returns empty vector on failures (random generation, key derivation, encryption errors).

---

### `static std::string Decrypt(const std::vector<uint8_t>& encryptedBlob, const std::string& masterPassword)`

Decrypts an encrypted blob back to the original JSON plaintext.

- Validates blob size, magic bytes, and version.
- Extracts salt, IV, ciphertext, and GCM tag from blob.
- Derives AES key using PBKDF2-HMAC-SHA256 with extracted salt and master password.
- Decrypts ciphertext with AES-256-GCM and verifies tag.
- Returns plaintext string on success.
- Returns empty string on failure (invalid blob, wrong password, corrupted data, decryption errors).

---

## Error Handling

- Uses logging (e.g., `LOG_CORE_ERROR`) to report errors in key derivation, random generation, encryption, or decryption steps.
- Returns empty results on failure for safe API use.

---

## Security Notes

- Uses strong 256-bit AES-GCM symmetric encryption with authentication.
- Employs PBKDF2 with 100,000 iterations to resist brute-force attacks on password-derived keys.
- Clears sensitive key material from memory securely with `OPENSSL_cleanse`.
- Requires OpenSSL library.

---

## Usage Example

```cpp
std::string plaintext = R"({"key":"value"})";
std::string password = "strongMasterPassword";

// Encrypt
auto encryptedBlob = AIAssistant::KeyEncryption::Encrypt(plaintext, password);
if (encryptedBlob.empty()) {
    // Handle encryption error
}

// Decrypt
std::string decrypted = AIAssistant::KeyEncryption::Decrypt(encryptedBlob, password);
if (decrypted.empty()) {
    // Handle decryption error (wrong password or corrupted data)
}
```

---

## Dependencies

- OpenSSL (EVP, RAND functions)
- Standard C++ (string, vector, memory functions)

`AIAssistant`

# AIAssistant::Log Class Documentation

## Overview
The `AIAssistant::Log` class provides centralized logging functionality for the application using the spdlog library. It initializes and manages two separate loggers:

- **Engine Logger**: Named `"Engine"`, intended for core engine logs.
- **Application Logger**: Named `"Application"`, intended for application-level logs.

Both loggers output simultaneously to `std::cout` via an ostream sink.

## Features
- Uses spdlog's thread-safe multi-threaded ostream sink to write logs to standard output.
- Configures log pattern to omit color codes for compatibility with ncurses.
- Sets logging level to `trace` for maximum verbosity.
- Enables automatic flushing after every log at the trace level.
- Registers both loggers globally with spdlog.
- Ensures logs can be redirected via `std::cout` buffer manipulation externally.

## Public Interface

### Constructor
```cpp
Log();
```
Initializes the log sinks and creates both the Engine and Application loggers with the configured sinks and settings.

### Methods

```cpp
spdlog::logger& GetLogger();
```
Returns a reference to the Engine logger.

```cpp
spdlog::logger& GetAppLogger();
```
Returns a reference to the Application logger.

## Usage Notes
- The ostream sink writes to `std::cout`. Output redirection can be controlled externally, for example by replacing `std::cout`'s buffer in `JarvisAgent::OnStart()` to integrate with ncurses UI.
- Both loggers are registered globally with spdlog, allowing logging via spdlog APIs if needed.
- The log pattern includes full timestamp, logger name, log level, and message without color codes.

## Example
```cpp
AIAssistant::Log log;
log.GetLogger().info("Engine started.");
log.GetAppLogger().warn("Application warning message.");
```

# TerminalLogStreamBuf Class Documentation

Namespace: `AIAssistant`

---

## Overview

`TerminalLogStreamBuf` is a custom stream buffer class derived from `std::streambuf`. It captures output text, strips ANSI escape sequences, and conditionally logs the cleaned output to both a terminal manager and an optional file logger. It efficiently handles buffering and synchronization to ensure thread-safe file logging.

---

## Purpose

- Redirect and process stream output line-by-line.
- Remove ANSI escape codes from the output.
- Filter out empty or whitespace-only lines.
- Enqueue cleaned log lines into a `TerminalManager`.
- Optionally write cleaned log lines to a file with thread safety.

---

## Constructors

### TerminalLogStreamBuf(TerminalManager* terminalManager, std::shared_ptr<std::ofstream> fileLogger)

- **Parameters:**  
  - `terminalManager`: Pointer to a `TerminalManager` for enqueuing log lines.  
  - `fileLogger`: Shared pointer to an `std::ofstream` for file logging.

- Initializes the stream buffer with a terminal manager and an optional file logger.

---

## Protected Member Functions

### `int sync() override`

- Flushes the internal buffer.
- Strips ANSI codes from the buffered string.
- If the resulting string is non-empty and not whitespace only:  
  - Enqueues it to the terminal manager (if available).  
  - Writes it to the file logger with thread safety (if file logger is open).
- Clears the buffer.
- Returns 0 on success.

### `int overflow(int character) override`

- Handles individual characters appended to the buffer.
- On newline (`'\n'`), triggers `sync()` to process and flush the buffer.
- For other characters, appends to buffer.
- Returns the input character or `not_eof` on EOF.

### `std::streamsize xsputn(const char* data, std::streamsize count) override`

- Appends multiple characters to the internal buffer.
- If the appended data ends with newline, removes the newline and calls `sync()`.
- Returns the number of characters processed.

---

## Private Static Member Functions

### `static std::string StripAnsi(const std::string& input)`

- Removes full ANSI escape sequences safely from the input string.
- Recognizes escape sequences starting with `ESC (0x1B)` and ending with an alphabetic character.
- Returns the cleaned string without any ANSI codes.

---

## Private Members

- `TerminalManager* m_TerminalManager`: Pointer to terminal manager for log enqueueing.
- `std::string m_Buffer`: Internal string buffer accumulating output before flushing.
- `std::shared_ptr<std::ofstream> m_FileLogger`: Shared pointer to an output file stream for logging.
- `std::mutex m_FileMutex`: Mutex protecting file writes against concurrent access.

---

## Usage Notes

- Designed for integrating streamed output with terminal UIs and file logs.
- Efficiently handles partial input via buffer until newline-terminated lines.
- Thread-safe for file writes via internal mutex locking.
- Automatically ignores empty or whitespace-only lines after ANSI stripping.
- Requires a valid pointer to `TerminalManager` if terminal logging is desired.
- File logging is optional; works if `fileLogger` is valid and open.

---

This class simplifies capturing, cleaning, and routing console or program output for combined terminal display and persistent file logging.

# TerminalManager Class Documentation

Namespace: `AIAssistant`

---

## Overview

`TerminalManager` is a C++ class providing terminal-based user interface management using the `pdcurses` library. It supports displaying a split view terminal window with a scrollable log section and a dynamic status section. The class handles initialization, rendering, resizing, and shutdown of terminal UI components. It manages log entries safely with concurrency in mind, and allows clients to supply custom status display data via callbacks.

---

## Key Features

- Initializes and configures terminal windows for logs and status.
- Thread-safe log message queuing and rendering.
- Resizes and recreates windows dynamically on terminal size changes.
- Supports color theming with a configurable green color.
- Allows clients to provide custom status content and control status area height using callbacks.
- Provides methods for normal rendering and paused mode rendering with status updates.

---

## Public Types

### `StatusLinesCallback`

```cpp
using StatusLinesCallback = std::function<void(std::vector<std::string>& lines, int maxWidth)>;
```

Callback type for supplying status lines to display.  
Parameters:  
- `lines` (output) - vector to fill with status lines (strings).  
- `maxWidth` - maximum width available in columns.

---

### `StatusHeightCallback`

```cpp
using StatusHeightCallback = std::function<int(int totalRows)>;
```

Callback type for deciding the height in rows of the status area.  
Parameters:  
- `totalRows` - total rows available in the terminal window.  
Returns:  
- Height of the status window (minimum 1).

---

## Public Methods

### `TerminalManager()`

Constructor. Creates an uninitialized terminal manager instance.

---

### `~TerminalManager()`

Destructor. Calls `Shutdown()` to properly release terminal resources if initialized.

---

### `void Initialize()`

Initializes the terminal interface and prepares windows for rendering.  
Performs locale setup, disables cursor, configures input modes, and sets up colors.

---

### `void Shutdown()`

Shuts down the terminal UI cleanly. Deletes all windows and resets terminal state.  
Safe to call multiple times.

---

### `void Render()`

Renders new log lines and status section.  
Detects terminal resize and recreates windows if needed.  
Renders all queued log lines in a batch, then draws the status window.

---

### `void RenderPaused(int counter)`

Renders UI in a paused state. Displays a paused message and a counter in the log area.  
Also renders the status section.

---

### `void EnqueueLogLine(const std::string& line)`

Adds a log line to the queue to be displayed in the next render pass.  
Thread-safe for concurrent logging.

---

### `void SetStatusCallbacks(StatusLinesCallback statusLinesCallback, StatusHeightCallback statusHeightCallback)`

Sets callbacks for providing status content lines and status window height.  
Triggers window recreation to adjust layout accordingly.

---

## Internal Behavior Details

- Maintains four windows using `pdcurses`:
  - Log header (fixed 1 row)
  - Log content (scrollable)
  - Status header (fixed 1 row)
  - Status content (height decided by callback)
- Log content is rendered in green color if supported.
- Automatic scrolling occurs when log lines exceed window height.
- Status lines provided by `StatusLinesCallback` are drawn line-by-line.
- Terminal resize events trigger window resizing and layout recalculation.

---

## Usage Scenario

1. Create `TerminalManager` instance.
2. Call `Initialize()`.
3. Optionally set status callbacks with `SetStatusCallbacks()`.
4. Repeatedly call `EnqueueLogLine()` from one or multiple threads to log messages.
5. Regularly call `Render()` to display updates.
6. On pause events, call `RenderPaused()`.
7. On application shutdown, call `Shutdown()`.
